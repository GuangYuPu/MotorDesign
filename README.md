## 五条使用规则

1. **先写现象，再写结论。** 现象要能被别人复现：工况、电流、温度、转速、照片。
2. **每条记录必须有「下次怎么避免」。** 没有改进项的记录等于日记。
3. **数字必须带单位和测试条件。** 「温升有点高」是废话；「@1200rpm/40N·m/25℃环境，绕组 118K，热点在端部」才是数据。
4. **不确定就标 `?`，不要编。** 供应商说的、你猜的、你测的，分三档写清楚。
5. **一条一文件，索引用 CSV。** CSV 负责排序筛选，MD 负责放细节和照片路径。

## 每条记录的最小闭环（最重要的一条）

一条记录只有走完这四步才算完成：

```
现象记录 → 根因判定（可证伪） → 改进措施 → 验证结果（改好了没有，怎么证明）
```

大部分人的库停在第一步。**决定段位的是第四步。**

## 第一周先做什么

1. 通读 `06-速查卡/` 四张卡，看不懂的记进 `08-路线与复盘/疑问清单.md`。
2. 打开 `01-失效库/待查-常见失效模式清单.md`，把**你已经见过**的打勾（多数人第一次能勾 3~5 个，这就是你的存量）。
3. 挑一台你设计过的电机，按 `04-实测对标/模板-仿真实测偏差.md` 建第一条记录（仿真侧可以先填）。
4. 把你此刻最想不通的 3 个问题写进 `08-路线与复盘/疑问清单.md`。

## 关于 CSV

- CSV 是**索引视图**，用 Excel / WPS 打开可排序筛选；MD 是**正文**。
- 每个 CSV 里有一行以 `示例-` 开头，看完删掉即可。
- CSV 已存为 **UTF-8 with BOM**，Excel 直接双击不会乱码。若你的工具仍乱码，用「数据 → 从文本/CSV」导入并指定 UTF-8。
